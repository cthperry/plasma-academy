#### 3.2 / A19 實作紀錄

A19 沿用 profile-engine,只在兩組參數之間交替 —— scallop 不必寫任何規則。
但過程補上兩個引擎參數,都是「用介電質的係數去跑矽」跑出來的問題:

| 問題 | 修法 |
|---|---|
| 沉積步一輪就把溝封死,深度只有 1 列 | `polySputterRel`(預設 1):聚合物濺射係數 0.03 是照介電質校準的,那裡靠 SiO₂ 自身的氧清聚合物;**矽沒有氧**,只剩這一項,Bosch 的清底步需要更高的倍率 |
| 關掉沉積步側壁只鼓 10 %,課文說「立刻被咬爛」 | `chemRel`(預設 1):0.35 是照氟碳化學校準的,而 **SF₆ 對 Si 又快又等向**,那正是 Bosch 要分步的理由 |

**規格層面補上一項**:docs/03 寫「循環時間短 → scallop 小,但產率低」。
第一版模型跑出來是**反過來的** —— 短循環 scallop 小、每秒深度還更高,
那 Bosch 就沒有理由用長循環。少的是**每循環固定的切換開銷**
(換氣、抽殘氣、電漿穩定,模型取每次 0.6 s)。加上之後短循環的開銷佔比
19 % vs 長循環 6 %,課文的結論才成立。**讓 trade-off 成立的是機台,不是化學。**

`tools/check-bosch.mjs` 13 項已進品質門,兩個觀察點都被斷言。

#### A18 實作紀錄(進行中)

「必須能重現八種 profile」比預期難得多,而難的地方不是畫圖,是**引擎的物理不夠對**。
第一次實作跑出來只有三種成立。追下去修掉了五個實質錯誤(細節見 `docs/05` 的 A18 實作備註):

| 問題 | 修法 |
|---|---|
| 八種輪廓停在不同深度,三段寬度無法比較 | 改成蝕到終點再過蝕刻 10 % 才量 |
| ARDE 幾乎不存在(落差 < 2 %) | 離子輔助項補上**本地**自由基覆蓋率(Langmuir);落差變 39/51/67 |
| 側壁的聚合物被無離子地清掉 | 氧消耗聚合物加上離子閘 —— 這才符合 3.1.4 |
| 遮罩中途被濺鍍光,低鈍化預設全變 faceting | 遮罩 chem 0.06→0.01、ionY 0.35→0.18、厚度 0.16→0.20 |
| faceting 與 undercut 用三段寬度分不開 | 新增「遮罩開口(倍)」讀數作為判別 |

**規格本身也錯了一處**:原本把 bowing 歸因於「鈍化不足」,但低鈍化會讓頂部先被咬開,
量出來是 undercut。bowing 要成立,頂部必須被沉積保護、中段靠離子反射打開 ——
所以 bowing 的鈍化必須**偏高**。這種錯誤純看文件永遠找不到。

配套產出:
- `src/js/lab/profile-shapes.js` —— 物理與 UI 分離,讓驗收條件可以被自動斷言
- `tools/check-shapes.mjs` —— 驗收測試,跑的是與瀏覽器同一份程式碼(尚未達成,故不進品質門)
- `tools/shapes-search.mjs` / `shapes-sweep.mjs` —— 在受限參數空間搜尋預設(開發工具,不進門)

#### 這一輪補上的物理(四項,全部是實作才浮現的)

1. **濺鍍產額的角度依賴 Y(θ)** —— 課文 3.1.6 教了整整一節,引擎裡卻沒有。
   用 Yamamura 型 `(1/cosθ)^3 · exp(−1.5(1/cosθ−1))`,峰值在 60°、約 1.8 倍。
   加上之後 faceting **才是真的削出斜面**,而不是靠「遮罩整體變薄」冒充。
2. **物理濺射與離子輔助化學蝕刻的角度依賴必須分開。** 第一版把完整的 Y(θ)
   也套在化學項上,結果任何斜面都被清得特別快,溝變成**完美矩形** ——
   比真實製程乾淨太多,taper 與 footing 直接被抹平。
   化學項改用 `1 + 0.35(Y−1)`(它由自由基覆蓋率主導,不是由反衝原子噴不噴出來
   決定),taper 與 footing 立刻成立。**這一項讓成立數從 4 變成 5。**
3. **再沉積(redeposition)** —— 從溝底打下來的材料會落在附近表面上重新黏住,
   落點集中在溝的下半段。這是 taper 與 footing 的機制之一。
4. **鏡面反射的通量門檻寫得太高**(`inc.f <= 0.02` 就跳過)。側壁的直射通量
   本來就小,但它是**掠射**進來的、反射比例最高 —— 正是要抓的那一份。改為 0.002。

#### 三種未收斂的**具體診斷**(供接手者直接動手)

- **Undercut**:A18 的膜是 SiO₂,而 **F 自由基蝕 SiO₂ 需要離子先破 Si–O**
  (這正是 3.1.4 的化學選擇性),所以純化學側蝕本來就很小 —— 模型是對的,
  是**題目選錯材料**。undercut 是 poly-Si / Al 蝕刻的缺陷,不是介電質蝕刻的。
  → **修法:讓 A18 的目標膜可選(Si / SiO₂ / SiN)**,在 Si 上示範 undercut。
  這同時讓 A18 能示範選擇比,教學價值比硬湊 undercut 高。
- **Bowing / Microtrench**:兩者都需要側壁處於**部分保護**的狀態,
  但目前 `poly` 在側壁會累積到 4×polyCrit,`block = 1 − poly/polyCrit` 直接飽和成 0
  —— 模型只有「完全保護」與「完全清開」兩態,沒有中間的梯度,
  所以側壁不可能出現「中段比上下段多被咬一點」。
  → **修法:讓側壁的聚合物有上限(例如 clamp 在 1.2×polyCrit)**,
  使 block 落在 0…1 之間可變;或讓聚合物本身會被斜射離子緩慢濺射掉。
  這一改會動到 etch-stop 的邊界,要一併重新確認 F/C 分水嶺。

#### Undercut:目標膜已可選,但**判定**卡住(第三條記錄)

`profile-shapes.js` 已支援 `state.film`(oxide / silicon / nitride,見 `FILMS` 與 `layersOf`),
下層自動配對(矽膜配氧化層下層 = poly gate;氧化膜配矽下層 = 接觸孔)。
同時補了 `paramsFor(state)`,讓 `state.engine` 可以覆寫引擎參數 ——
從外面覆寫 `S.stepParams` 沒有效果的那個坑就此拔掉。

**在矽膜上側蝕確實出現了**(這是對的:silicon 的 `chem` 是 1.0、oxide 只有 0.25):
undercut 預設在矽膜上量到頂部 **257 %**、中段 114 %、底部 43 %。氧化膜則是 100/100/100。
所以「undercut 要在 Si 上示範」這個判斷成立。

**但 `classify()` 把它判成 Faceting**,原因是**判別指標本身有缺陷**:

- `maskMetrics().widen` 量的是**遮罩最下一列**的開口寬。膜被側蝕之後,
  遮罩下方變成懸空的簷,那一列很快就被從下面咬開 → widen 衝到 2.57,
  越過 `> 1.25 → Faceting` 的分支。
  **而 widen 這個指標當初就是為了把 faceting 和 undercut 分開才加的** ——
  它現在對 undercut 也有反應,等於失去了鑑別力。
- 直覺的修法「改量遮罩**最上面**那一列」**也不對**:實測氧化膜的 undercut
  (判定為垂直、widen = 1.00)openTop/base 已經是 **2.86**,
  遮罩肩部 `shoulderRatio` 甚至是 0.00。也就是說遮罩上緣在各種預設下都會被削,
  上緣寬度同樣分不開兩者。
- 掃描 100 組(ion 200–900 × radical 15–95 × passiv 0–28,矽膜)
  **沒有任何一組**同時滿足「頂部 > 125 %」與「widen ≤ 1.25」。

→ **下一步不是再調參數,是重新定義 faceting 的判別**。
可能的方向:比較遮罩**剩餘厚度的橫向分布**(faceting 是肩部薄、遠處厚的斜面),
而不是比較開口寬度 —— 開口寬度同時被兩種缺陷推動,先天分不開。
`fieldLeft` 與 `shoulderRatio` 已經量好了,但目前只在 faceting 分支後面才用到。

#### 試過但**沒有用**的兩條路(別再走一遍)

1. **加強再沉積(redeposition 0.5 → 10)**:完全沒有差別。原因是側壁的聚合物
   已經飽和(`block = 0`),再多疊一層擋不住更多東西 —— 它是 no-op。
2. **聚合物自發損失(polyLoss 0.05 / 0.15 / 0.4)**:動機是讓側壁膜厚有穩態值、
   讓 `block` 出現梯度。實測**不足以讓側壁出現「中段多被咬一點」**,
   而且會把 taper 的製程窗推掉(taper 變成 footing)。引擎保留這個參數並註明,
   但 `profile-shapes.js` 刻意不開。

**要動 bowing / microtrench,必須連 `block` 的飽和一起重新設計**,
單獨加機制沒有用 —— 上面兩次都是這樣失敗的。

> ⚠️ **探測工具的坑**:`S.stepParams = ...` 從外面覆寫**沒有效果**,
> 因為 `step()` 呼叫的是模組內部的 `stepParams`。要試新參數必須直接改
> `profile-shapes.js`。前兩次探測就是踩到這個,得到「參數無效」的假結論。

**這一項仍必須在 3.3 缺陷圖鑑完成前收斂** —— 圖鑑的診斷區分要靠 A18 驗證,
模擬器做不出來的形狀,圖鑑就沒有依據。3.1 的課文已如實標註目前的限制。

**這一項必須在 3.3 缺陷圖鑑完成前收斂到八種全綠** —— 圖鑑的診斷區分要靠 A18 驗證,

### 3.4 電漿沉積完成紀錄

`deposit-model.js` 是獨立於 `profile-engine.js` 的一支(蝕刻只會移除,沉積要往真空側長),
骨架同樣只有三條規則:**抵達**(黏著係數決定通量分布)、**長厚**、**濺掉**(只有 HDP)。
四種製程只是這三條的不同參數,void / cusping / 同形 / 由下往上填滿都沒有被單獨寫成規則。
由 `tools/check-deposit.mjs` 的 24 項斷言守住,已進品質門。

#### 建這支模型時抓到的四個 bug(都是量測假象,不是物理)

1. **場區的膜頂到格點上緣** —— 頂部空間只有 21 列,約 130 步後膜就把上方填實,
   `viewFactor` 看不到天空全部歸零,四種製程只剩「被遮住時的殘餘通量」在跑。
   結果**看起來很漂亮**(全部填滿、零空洞),而且濺鍍項變成完全無效
   —— 開與關的 void 數一格不差。
   → 格點尺寸改由「要沉積多厚」反推,並且只長到 budget 就停。
2. **左右邊界當成固體牆** —— 蝕刻引擎這樣寫沒問題(牆就是牆),沉積不行:
   最外面那一欄每一列都變成「貼著固體的真空格」,兩側自己長出一道膜牆往內爬,
   場區膜厚的探針量到的是那道牆(26 格的預算在 36 步就「達到」)。
   → 改成**鏡射邊界**,物理意義是「一整排相同的溝」。
3. **濺鍍與沉積算在不同格** —— 原本寫成「沉積長真空格、濺鍍削固體膜」兩個獨立迴圈。
   沉積 6 步就把那格膜埋起來,而削掉一格要 11 步,累積的 −0.55 就此凍結,
   永遠碰不到門檻:**埋得比削得快,濺鍍就等於沒寫**(統計到 5965 次「削除」、
   總量 550,實際移除 0 格)。
   → 兩項合併成同一個表面格的**單一淨值**,淨值才是課文講的 dep/sputter ratio。
4. **階梯覆蓋率被量化** —— 量覆蓋率時膜厚只有兩三格,純數格子的比值被量化成
   0.00 / 0.33 / 0.50 這種階梯,同一個製程換個 AR 就跳一大階,看起來像物理其實是解析度。
   → 改成**連續膜厚**(整數格數 + 正在長的那一格的分數,模型本來就記在 `grow` 裡)。

還有兩個**斷言本身寫錯**的地方,是靠實測才發現的:
「TEOS 每一種 AR 都留空洞」(把 TEOS 說得太差了 —— 它填得掉低 AR 的溝,
那正是中等節點用它就夠的原因)、
「HDP 合攏時填充很低、不是靠同形」(修好濺鍍之後 HDP 其實是由下往上填,
合攏時已填 54 %,原本的說法反而變成錯的)。

#### 比較點的選擇:同樣的**淨沉積厚度**

四種製程一律長到「場區膜厚 = 溝寬 × 1.5」才比(同形填滿只需 0.5 倍,所以是三倍餘裕)。
不用「各自跑到停滯」有三個理由:會觸發上面第 1 個 bug、現場比填溝也是在同樣膜厚下比、
HDP 的場區成長率本來就被濺鍍扣掉一截,用同樣淨厚度正好把它一起正規化掉
(實測 HDP 要花 2.0 倍步數才長到同樣淨厚度 —— 這就是 D/S ratio 的代價)。

⚠️ 預算必須是**溝寬的固定倍數**。寫成 `width + 4` 會讓窄溝拿到相對更多的膜
(AR 8 是 1.7 倍溝寬,AR 2 只有 1.2 倍),高 AR 反而佔便宜。

#### A23 的已知不足:HDP 的深寬比極限沒有重現

`docs/05` 的 A23 驗收條件寫著「AR 調到 8 → 連 HDP 也填不進去」,
**這一條沒有達成** —— 模型的 HDP 一路到 AR 10 都填得滿。

真實機制是濺出來的材料在溝口附近堆成一頂帽子而重新夾出 void。
目前的落點規則是「沿深度指數衰減、權重 (1 − 視角因子)」,
已經比原本的「按 (1 − vf) 分給全場」好(那條規則等於把材料無條件送到最深處,
是它讓 HDP 在任何 AR 都填得滿),但仍不足以長出帽子。
→ **要收斂必須把濺出通量的角度分布與直線飛行完整算出來**,
單純調衰減尺度沒有用(已試過 λ = 溝寬)。

3.4 的課文已如實標註這一點,並明講「A23 在極高 AR 的 HDP 結果是樂觀的,
不要拿它當製程窗的依據」。A22 的四項驗收條件則全部達成。

### 3.5 濺鍍 PVD 完成紀錄

`magnetron-model.js` 把整章收斂到**一個無因次參數**:Hall 參數 h = ω_c·τ,
等效路徑放大 (1+h²)。磁控的效率、它為什麼喜歡低壓、racetrack 為什麼在那個半徑、
靶材利用率為什麼只有兩三成 —— 全部是這一條的後果,不是四條獨立規則。
由 `tools/check-magnetron.mjs` 的 24 項斷言守住,已進品質門。

**反應式濺鍍的遲滯:第一版完全算不出來。**
只寫靶面收支時,穩態解 Q(θ) 是單調的,升流量與降流量走同一條線,沒有雙值區。
正回饋根本不在靶面,在**氣體收支**,而且要三件事同時成立:

1. 只有裸金屬會 gettering,而**腔壁+基板的面積遠大於靶面**(模型 as/at ≈ 15)
2. 基板上的化合物靠**新到的金屬**埋掉,金屬通量 ∝ 靶面裸露比例
3. 化合物的濺鍍產額只有金屬的 1/6

於是「靶中毒 → 金屬通量崩掉 → 基板也中毒 → 沒人吃氣體 → 分壓暴漲 → 靶更中毒」。
把 as 調回靶面的量級,雙值區立刻消失 —— 這條對照直接寫成斷言,
確保遲滯是機制產生的,不是參數湊出來的。
實測雙值區 15.25–19.75 sccm,兩支的沉積率差 2 倍以上。

⚠️ 掃描發現 as 要到 20 以上雙值區才出現。這不是為了好看而調大:
真實機台的腔壁+基板面積對靶面面積本來就是這個量級。

**A24 的視角選擇**:取「把 racetrack 攤平」的剖面(水平軸 = 繞環的方位方向,
B 垂直畫面)。軸對稱的 r–z 剖面裡 E×B 漂移是**出平面**的,
在那個視角畫擺線是錯的 —— 這一點值得記住,教科書插圖也常畫錯。

### 3.6 均勻度完成紀錄

六種 map **不是六個選項**,是八個物理旋鈕疊加的結果;
判定(classify)看量出來的 map,不看使用者選了哪個預設 —— 與 A18 同一個原則。
`tools/check-uniformity.mjs` 21 項斷言,已進品質門。

#### 三個「指標本身有缺陷」的修正(都是實測才發現的)

1. **Edge roll 不能量「外圈 − 肩部」。** 中心快的剖面本來就一路往下掉,
   最外圈當然比肩部低 —— 用這個當判據,**每一張 bull's eye 都被誤判成 edge roll**。
   改成「拿 r = 0.5…0.85 的線性趨勢外推到最外圈,量殘差」之後,
   真的 edge roll 量到 0.54,其餘五種都在 0.05 以內,差了十倍。
2. **環紋不能數「斜率變號次數」。** W 形的斜率也會變號,兩者分不開。
   改成數「二階差分的尖峰」,而且門檻要**相對於背景曲率**(取中位數的 4 倍)——
   用固定門檻時,平緩的 W 形反而數到比銳利的環紋還多。
3. **兩個供應高斯要夠寬、夠重疊。** 原本取 0.55 / 0.45,兩個高斯在中間半徑
   都衰減掉,於是「只有氣體項」也會凹出一個假的 W ——
   那樣「W = 中心快 + 邊緣快疊加」的論述就落空了。放寬到 0.75 / 0.62 之後,
   單獨的氣體項是單調的,W 真的需要電場項才長得出來(斷言直接驗這件事)。

另外修掉一個**課文與數字對不上**的地方:Arrhenius 的 Ea 原本取 0.2 eV
並註解「每 10 °C 約差 8 %」,實際算出來是 22.5 %。改成 0.12 eV(13 %)並更正註解。

`controls.js` 原本沒有 **button** —— slider/segmented/toggle 都是「設定一個值」,
但 A25 的反向練習是「做一件事」(重新出題)。補了 `C.button`,
用 `.pa-seg` 當容器沿用既有按鈕樣式。

瀏覽器煙霧測試抓到)。要共用的工具函式放 closure。

### 3.3 缺陷圖鑑完成紀錄

**P3 到此全部完成**(3.1–3.7 七章)。

`arde-model.js` 把 ARDE 拆成四個可以**個別關掉**的傳輸限制,

四項全關時 ARDE 歸零。`tools/check-arde.mjs` 18 項斷言,已進品質門。

#### 建模時抓到的三個錯

1. **不能用固定時間比 ARDE。** 速率寫成 1/(1+k·AR) 時,積分的漸近解是
   d ∝ √w,**與 k 完全無關** —— 跑得夠久之後不管怎麼調旋鈕,ARDE 都收斂到同一個值
   (實測五種預設全部落在 62–63 %,看起來像「所有旋鈕都沒用」)。
   改成「蝕到最寬的那條達到目標深度」就正常了 —— 這也是現場真正的比較點。
2. **壓力沒有接到離子角度發散上。** 原本 divTan 是獨立參數且預設不動,
   於是「降壓」只改到產物排出那一個小項,ARDE 幾乎沒變 ——
   等於把這一章最常用的旋鈕講廢了。改成 θ ≈ 1.5° + 1.1·√P。
3. **CD 範圍拉太開。** 原本 1.0…0.25,最寬的刻到 AR 3 時最窄的已經 AR 12,
   四個傳輸限制在那裡全部飽和,任何旋鈕都救不動。
   改成 1.0…0.4(AR 3…7.5),才是真實 ARDE 研究的比較尺度。

#### 未達成:反向 ARDE 沒有翻負

模型做得到「高聚合區把 ARDE 壓小」(27 % → 18 %),做不到「窄的反而更深」。

原因:聚合物在 AR→0 時供應最大,所以在它強到足以**翻轉深度排序**之前,
會先把最寬的溝在開口就封死 —— 那是 etch stop,不是反向 ARDE。
試過三種寫法都卡在同一個地方:
  · 除法折扣 `傳輸 ÷ (1+鈍化)` —— 鈍化只能按比例壓小,永遠翻不過傳輸限制
  · 相減競爭 —— 有效,但窄溝的 removal 本來就小,相減對它的相對傷害更大
  · 把聚合物黏著係數與自由基脫鉤(0.85)—— 方向對了,壓小的幅度變明顯,仍未翻負

→ **要收斂必須把「離子驅動的聚合物清除」也寫進去**,而那一項會把深度依賴
反轉回來,所以需要完整的聚合物收支(供應與清除都隨 AR 變),不是這支一維模型的範圍。
check-arde 把「目前仍為正」寫成斷言 —— 哪天做到了那條會失敗,提醒接手的人更新課文。

#### A21 診斷器:判別方法是**組出來**的,不是另外寫一份

`defects.js` 新增 `FLOW_TESTS`(依類別給的診斷流程實驗)與
`methodsFor(id)` / `rank(id, cond)`。判別方法由三個來源組合:
圖鑑的「診斷區分」欄 + 對每個相關缺陷的比對 + 該類別的流程實驗。
**實測每種缺陷最少 4 個判別方法**,超過規格要求的 2 個。

`rank()` 的條件只調整**排序**,不刪選項 —— 這是 docs/05 明列的設計要求:
輸出必須誠實顯示「這個症狀有多個可能成因」。數值面板也刻意顯示

`tools/check-diagnostics.mjs` 28 項斷言,已進品質門。

**A26 的四個參數全部由曲線算出來**(findVf / fitTe / findVp / neFromIsat),
不是把設定值抄回來顯示 —— 所以「量錯」是可能的,這正是探針教學的核心。
補償正常時誤差 < 0.1–2.5 %,四種氣體(Ar/O₂/CF₄/Cl₂)都準,
因為離子質量真的進了 Bohm 速度。

#### A26 未達成的驗收條件(可證明做不到)

docs/05 寫「無 RF 補償時 T_e 高估至少 2 倍」。**本模型做不到,而且是可以證明的:**

    ⟨exp((V − V_p − V_rf·f(t))/T_e)⟩_t = exp((V − V_p)/T_e) · ⟨exp(−V_rf·f/T_e)⟩

後面那一項**與 V 無關**,所以任何波形(不只正弦)的 RF 調變在指數區
都只是把曲線整條平移,**斜率完全不變** → T_e 救得回來。
實測 V_rf 從 0 掃到 45 V,T_e 誤差始終在 2 % 以內;
改用貼著轉折的擬合窗也只高估 5–13 %,離 2 倍差很遠。

要讓 T_e 真的被高估,需要模型裡沒有的物理:探針雜散電容分壓、
非 Maxwellian EEDF、探針座面積效應。

**但模型確實抓到一個同樣嚴重的錯誤**:V_rf = 30 V 時
**V_p 從真值 20 V 被量成 −10 V**(差 30 V),V_f 同步平移。
而離子能量 ≈ V_p − V_wafer,所以下游估計全錯。
check 把「T_e 目前沒有被高估」寫成斷言 —— 哪天補上缺的物理,那條會失敗提醒更新課文。

#### A27:actinometry 兩個價值都驗到了

功率 500→1200 W:絕對強度變 55 %、比值只變 2.4 %(差 23 倍)。
視窗透光率 1.0→0.3:絕對變 70 %、**比值完全不變**(視窗透光率同乘在分子分母,精確抵消)。
第二項在現場比第一項更常救人 —— 觀測窗積膜是必然發生的。

另外驗了**失效條件**:改用 Si(5.1 eV)當內標比 F(14.5 eV),
比值的敏感度變成正確內標的三倍以上 —— 直接驗證 4.1.4 的第二個前提。

⚠️ 建模時發現的一件事:強度只寫成 `濃度 × n_e × exp(−E_th/T_e)` 是不夠的。
低閾值物種會壓倒一切,實測 SiO₂ 蝕刻最亮的變成 C₂(2.5 eV)與 Si,
而課文說的主訊號是 CO 與 F。加上**譜線本身的相對強度**(截面與躍遷機率,
真實譜線本來就差好幾個數量級)之後,各製程最強的線才和 4.1.3 對得上。


### 4.2 終點偵測與 APC 完成紀錄

A28 的兩條驗收條件都達成,`tools/check-endpoint.mjs` 35 項斷言全綠。

模型的核心只有一句話:**OES 訊號 ∝ 開口率,而偵測器雜訊是絕對值**。
其餘全部是這句話的後果 —— SNR ∝ 開口率,開口率掉兩個數量級 SNR 就掉兩個數量級。
干涉訊號的計算式裡沒有開口率這一項,所以它的終點時間在四個數量級的開口率上
**逐位元相同**(101.1905 s),這一條可以用等號斷言而不是容差。

#### 「不可靠」必須用統計驗,單次結果會騙人

第一版的探針用單次 `detect()`,結果誤差跨好幾個數量級的開口率都給同一個離散值
(−0.7 % → −53.6 %),看起來像模型壞掉。實際上「低 SNR 下不可靠」本來就是
**統計陳述**:同一組參數跑 24–40 顆種子,看中位誤差與**失敗率**(誤差 > 10 %)
才驗得準。加上 `reliability()` / `reliabilityInterference()` 之後,
OES 失敗率隨開口率單調上升 0 → 18 → 70 → 88 → 90 %,而干涉全程 0 %。

這件事直接寫進課文與 A28 面板:元件同時顯示「這一次的誤差」與「24 次的失敗率」,
並提供「重新取樣」按鈕 —— 對應現場那個真實的誤判:
**工程師拿一片切片正常的晶圓,結論「終點沒問題」**。

#### 實作逼出來的三個修正

1. **原規格的四個演算法選項有三個是同一件事。** 「移動平均 / 一階微分 / 歸一化」
   實測跑出**位元完全相同**的結果:微分法本來就要先平滑,而歸一化只是除以常數、
   argmax 對縮放免疫。歸一化救的是跨片視窗霧化漂移,不是單片的終點時間。
2. **平滑必須是「拖尾」才有延遲代價。** 置中平滑 31 點的有號偏差只有 −0.05 %,
   因為對稱平滑不移動對稱轉折的反曲點。真機控制器看不到未來的取樣點,
   改成拖尾(因果)之後:不平滑 +0.02 %、9 點 +1.25 %、31 點 **+4.64 %**。
3. **誤差最小的判準不能拿來停機。** 「平台間 50 % 門檻」在 0.3 % 開口率時誤差 0.7 %
   (微分法已經 56 %),但它要用到蝕刻**結束後**的平台,是非因果的。
   模型用 `causal` 旗標標記,課文明確區分即時法與事後法 ——
   這也解釋了為什麼事後重新分析的終點時間會和機台當下報的不一樣。

#### 干涉法自己的失效邊界(與開口率無關)

- **條紋預算 < 1 個週期**(SiO₂ @ 633 nm 就是 216.8 nm)時直接回報
  `usable: false`,不硬給數字。膜厚 150 nm 只有 0.69 個條紋。
- **固有時間解析度 = λ/(2n) ÷ 蝕刻率**,SiO₂ @ 5 nm·s⁻¹ 是 43 秒。
  振幅塌陷是一段斜坡而非一瞬間,誤差大小隨「膜厚 ÷ 週期 的小數部分」起伏。
  這也是為什麼干涉的失敗判準用「一個條紋週期」而不是和 OES 一樣的 10 % ——
  拿 10 % 去要求它是在罰它做不到的事。

實作時另一個被實測推翻的直覺:第一版把時間戳掛在振幅窗的**起點**
(理由是「這個窗往前看」),結果系統性早報半個窗(−22.6 %);
掛終點則系統性晚報。掛中點才是無偏的。

### 4.3 電漿誘發損傷完成紀錄

A29 的第一條驗收條件達成;**第二條被實作推翻**,`tools/check-charging.mjs` 31 項斷言全綠。

模型的骨幹是一條算得出來的因果鏈:電子等向、離子垂直 → 幾何穿透率 1/(1+AR²)
→ 電位天花板 V = −T_e·ln(有效電子收集係數) → 沿導線灌進閘極 → 注入電荷累積到 Q_bd。

#### ⚠️ 原規格的「天線比與閘極電位近似線性」不成立 —— 線性掛錯了對象

實測 log-log 斜率(天線比 10 → 3000):**電位 0.078、注入電荷 0.979、到崩潰 −0.979**。
天線比 100 → 1000:電位只多 19 %,劑量剛好 ×9.5。

物理上必然如此:電位由天花板(T_e 與深寬比)決定,而氧化層導通對電壓是指數的;
天線比改的是單位閘極面積要吞多少電流 —— 那是**劑量**,不是電位。
這正是設計規則寫成面積比上限的理由,也直接推翻現場那句
「電位只多了 10 %,應該還好吧」。課文與元件因此同時給兩個讀數,
並把原規格的錯誤釘成反向斷言。

#### 沒有氧化層漏電,天線比在物理上是無效的旋鈕

第一版只放 FN 穿隧,天線比從 10 掃到 3000,電位與劑量**一位數都沒變**。
不是數值問題,是結構問題:浮動天線的電位被電漿自己釘住(電漿導納 ∝ 天線面積),
而驅動也 ∝ 天線面積,兩邊完全對消。天線比只能透過

    V_ox = V_天花板 × G_電漿 / (G_電漿 + G_氧化層)

這個**分壓器**生效,而 FN 式在直接穿隧區低估好幾個數量級,等於把 G_氧化層 設成 0,
分壓器退化。改用擬合公開閘極漏電 t_ox 標度的經驗式(1 V 下每 nm 約四個數量級)
之後,機制才成立。**這一項不是細節,是天線效應本身。**

#### 脈衝救得了磨耗失效,救不了硬崩潰

實測三種 duty 的尖峰電位**完全相同**(4.450 V),只有時間平均與劑量下降,
而劑量幾乎剛好等於 duty(20 % → 0.18)。所以要分兩種失效講:
硬崩潰是場強判準(瞬間),磨耗失效是電荷劑量判準(累積)。
原規格沒有這個區分,但它決定了對策選得對不對 ——
現場「脈衝之後崩潰率沒降」多半就是把硬崩潰當成磨耗在治。

#### Q_bd 必須隨 t_ox 變化,否則結論與現場相反

取常數會得到「1.5 nm 的核心元件比 10 nm 的 I/O 元件更容易被天線打死」。
加上「每薄 0.5 nm 約一個數量級」的公開趨勢後,模型跑出正確且反直覺的結果:
**最脆弱的是 4–5 nm 的中間厚度**(硬崩潰只發生在這裡),兩頭都有保護 ——
薄的靠自己的漏電把電位壓在 0.6 V,厚的把天花板電位除以厚度之後場強反而安全。

對策劑量比較(t_ox 3 nm、天線比 300、深寬比 5、全遮蔽):
天線二極體 ×1.2e−6、遮蔽比例降到 20 % ×1.5e−6、脈衝 duty 20 % ×0.18、低 T_e(1.5 eV) ×0.35。

τ(T_e) = 6.7 µs、τ(n_e) = 71 µs(比值 10.7),而且是**量出來的** ——

  這一點有測試背書,不是宣稱。
- **附著係數** 1.2e-16 → 電負度 α 跑到 1800。改成 8e-18 後 α 落在
  0.67(on)/ 3.9(off),後輝光的離子-離子電漿才是文獻上的樣子。

#### 一個與物理無關、但值得記的前端 bug

A30 第一版在瀏覽器裡直接炸掉:`Cannot read properties of undefined (reading 'label')`。
原因是 **rAF 的第一幀時戳可能早於 `start()` 裡取的 `performance.now()`**,
於是 dt 是負的、動畫相位變成 −1.5e−5,`Math.floor` 給 −1,`STEPS[-1]` 是 undefined。
負的 dt 是瀏覽器的正常行為。修法:正模數 + `Math.max(0, dt)`。
順帶抓到 dt 的單位是**秒**不是毫秒(原本除了 1000,動畫慢一千倍)。

其餘實測:壓力 2 → 200 mTorr,T_e 3.70 → 1.55 eV,E_c 34 → 513 eV;
腔體半徑 0.05 → 0.30 m,T_e 2.44 → 2.16 eV;
Ar 的 E_c 95 eV 最低,Cl₂ 405 eV 最高 —— 分子氣體難維持的定量原因。

#### 把理想結論的破口做成開關,而不是偷偷放進去

規格沒要求,但值得做:打開「氣體加熱」(高功率 → T_g 上升 → 定壓下 n_g 下降
→ n_g·d_eff 變小 → T_e 上升)之後,同一組功率掃描的 T_e 變化從 0.00 %
變成 **27 %**、n_e 線性偏差 21 %。開關預設關閉,課文明講它是理想 0-D
第一件會失準的事。**理想結論要先立得住,才談它什麼時候失準** ——
如果一開始就把加熱放進去,學員永遠看不到那個乾淨的恆等式。

#### 自由基平衡少了母氣體耗盡,會算出「自由基比氣體還多」

第一版跑出 SF₆ 的自由基密度是氣體密度的 **2957 %**。
正確寫法是解耦合平衡 f = k_d·n_e/(L + k_d·n_e),它自然被 f → 1 卡住。
改完之後解離度 O₂ 80 %、Cl₂ 86 %、CF₄ 90 %、SF₆ 97 %,與 ICP 文獻同量級。
(雙原子分子的自由基密度可以超過氣體密度 —— Cl₂ → 2Cl 給 171 % ——
但**解離度**必須 < 100 %,測試釘的是後者。)

### 4.6 量產、良率與安全完成紀錄

最後一章,沒有互動元件。但它有另一種正確性可以守:**交叉引用**。
五個故障情境全部引用了前面章節的結論(4.2.7 的五個 FDC 訊號、
4.3 的天線比與 I/O 元件、3.6 的 first wafer effect、4.4 的鞘層 ∝ T_e),
所以做成 `src/data/faults.js` 資料模組,由 `tools/check-faults.mjs`
驗那些引用真的指得到東西:21 項斷言全綠。

驗的東西包括:五個情境的九個欄位齊備、每條假設都附了怎麼驗、
引用的 FDC 訊號都存在、**五個訊號每一個都至少被一個情境用到**
(沒有列了卻用不上的)、引用的章節都在課綱裡、
每個根因都真的出現在章節頁上、GWP 表遞增且章節頁數字與資料一致。

這是「單一資料來源」原則在**純內容章節**上的應用 ——
數字與交叉引用一樣要被自動化守住,不能只靠人眼。

一個內容上的設計:五個情境的共同結構不是「看到異常訊號」,
而是**某一條線索排除掉了其他可能**(均勻度沒變差 → 排除局部堵塞;
只有邊緣不同 → 排除氣體與功率;FDC 完全正常 → 排除機台)。
章末把這五條並列,因為會看訊號的人很多,會用一條線索排除三種可能的人不多。

## 內容產出順序原則

在每一期內,順序固定:

```
1. 資料模組先行     gases.js / defects.js / spectra.js
2. 互動元件的物理模型   先確認計算正確,再做視覺
3. 章節正文          寫作時可即時引用元件與資料
4. SVG 示意圖        正文定稿後再畫,避免重工
5. 題目              最後,確保考的是實際寫進去的內容
```

**最常見的錯誤是先畫圖再寫文**,結果文章寫到一半發現圖不對,重畫。

## 風險與對策

| 風險 | 影響 | 對策 |
|---|---|---|
| **技術正確性審閱找不到人** | **最高** — 錯誤的教材比沒有教材更糟 | 專案啟動前就先確認審閱人選並排入時程;優先找有實際機台經驗者而非純學界 |
| 互動元件的物理模型過度簡化到誤導 | 高 | 每個元件的驗收條件都包含「與課文數值一致」;模型刻意誇大處必須在畫面標註 |
| A16、A18 複雜度失控 | 高 | 排在各期最後;先做最小可行版本(3 種狀態)再擴充;設定時間上限,超過就砍功能不砍品質 |
| 內容量遠超估計 | 中 | 每章設字數上限(4,000 字),超過就拆;5 分鐘摘要強制存在,確保趕時間的人也有收穫 |
| 術語與數值前後不一致 | 中 | 單一資料來源原則;建置時加自動檢查(數值出現在正文與資料模組時比對) |
| SVG 圖的品質不足以辨識缺陷 | 中 | P3 前先做 3 張樣圖給有 SEM 經驗者確認風格 |
| 深色模式的 Canvas 適配漏做 | 低但煩人 | 納入元件驗收清單;寫一支自動化檢查腳本切換主題後截圖比對 |
| 行動版互動元件不可用 | 低 | P0 就決定重新佈局策略;極複雜元件明確標示建議大螢幕 |
