# 07 — 設計系統

## 設計原則

1. **內容優先** —— 這是教材不是行銷網站。裝飾性元素一律讓位給可讀性
2. **長文閱讀最佳化** —— 工程師會連續讀 40 分鐘,行高、字級、行寬都以此為準
3. **圖表即內容** —— 互動元件與正文同等重要,不是插圖
4. **兩套主題等權** —— 深色不是附加功能。無塵室外的辦公區常年低照度,深色模式是主要使用情境之一
5. **不靠顏色傳達唯一資訊** —— 所有色彩編碼必須同時有形狀、標籤或圖案

## 色彩 Token

全部以 CSS 自訂屬性定義,深淺兩套。**元件一律使用語意 token,不直接寫色碼。**

### 語意層

```css
:root {
  /* 表面 */
  --pa-bg:            /* 頁面底 */
  --pa-surface:       /* 卡片、面板 */
  --pa-surface-raised:/* 浮起層(下拉、tooltip) */
  --pa-surface-sunken:/* 凹陷層(程式碼、公式卡) */

  /* 文字 */
  --pa-text:          /* 正文 */
  --pa-text-muted:    /* 次要說明、圖說 */
  --pa-text-subtle:   /* 標籤、單位 */
  --pa-text-inverse:  /* 深底上的文字 */

  /* 邊界 */
  --pa-border:        /* 一般分隔 */
  --pa-border-strong: /* 表格、輸入框 */

  /* 品牌與互動 */
  --pa-primary:       /* 主色,連結與主要按鈕 */
  --pa-primary-hover:
  --pa-focus:         /* 焦點外框 */

  /* 狀態 */
  --pa-info:  --pa-success:  --pa-warning:  --pa-danger:
}
```

**對比要求**:正文對背景 ≥ 7:1(AAA),次要文字 ≥ 4.5:1(AA),UI 邊界 ≥ 3:1。兩套主題都必須驗證。

`npm run check:contrast` 對 19 組前景/背景配對 × 2 套主題共 38 項自動驗證,不通過即視為未達標。

> **實作記錄**:初版規劃提出的色值有 6 項未達本文件自己訂的標準 —— `text-subtle`(兩處)、`primary` 對提示方塊底、`warning` 對提示方塊底、`border-strong`(深淺各一)。上表為驗證後的修正值。
> 其中 `--pa-border-strong` 用於按鈕、輸入框與表格表頭底線,屬 WCAG 1.4.11 非文字對比範圍,必須達 3:1;初版值僅 1.56:1,是最容易低估的一項。

|---|---|---|---|
| L1 初階 | 青 | `#0e8a9e` | `#3fc0d4` |
| L2 中階 | 藍 | `#2563c9` | `#5a9af5` |

## 排版

### 字型堆疊

```css
--pa-font-sans:
  system-ui, -apple-system, "Segoe UI", Roboto,
  "Noto Sans TC", "PingFang TC", "Microsoft JhengHei", sans-serif;

--pa-font-mono:
  ui-monospace, "SF Mono", Menlo, Consolas,
  "Noto Sans Mono CJK TC", monospace;
```

**不自行打包字型檔**。理由:中文字型檔動輒數 MB,離線與內網部署時是負擔;系統字型在目標使用者的環境(Windows/macOS 中文系統)表現足夠好。

### 字級

| Token | 尺寸 | 行高 | 用途 |
|---|---|---|---|
| `--pa-text-xs` | 12 px | 1.5 | 圖說、單位、標籤 |
| `--pa-text-sm` | 14 px | 1.6 | 表格、側欄、控制面板 |
| `--pa-text-base` | **16.5 px** | **1.85** | **正文** |
| `--pa-text-lg` | 19 px | 1.7 | 引言、摘要 |
| `--pa-text-xl` | 23 px | 1.4 | h3 |
| `--pa-text-2xl` | 28 px | 1.35 | h2 |
| `--pa-text-3xl` | 34 px | 1.25 | h1 |

**中文正文用 16.5 px / 1.85** —— 比一般英文站的 16/1.5 更大更鬆。中文字元密度高,行高不足會非常疲勞。這是刻意的取捨。

### 行寬

正文最大寬度 **68 個中文字元(約 700 px)**。超過會讓眼睛回行時找錯行。

表格、程式碼、互動元件可突破此限制,置中並允許自身橫向捲動。

### 中英文混排

- 中文與英文/數字之間**自動插入 0.15em 間距**(用 CSS `:lang()` + 字元類別處理,或撰稿時手動加空格)
- 英文術語使用 `<span class="term-en">` 標記,字重 500、字距 0.01em,與中文正文有微妙區隔但不刺眼
- 首次出現格式:`鞘層(Sheath)` —— 中文在前,英文在括號內

## 內容元件樣式

### 公式卡

```
┌─────────────────────────────────────┐
│ λ_D = √(ε₀ k T_e / n_e e²)          │  ← 置中,較大字級,mono 或襯線
│ Debye 長度                           │  ← 名稱
│ ────────────────────────────────    │
│ ▸ 展開推導與符號表                    │  ← 可展開
└─────────────────────────────────────┘
```

- 背景 `--pa-surface-sunken`,左邊界 3 px `--pa-primary`
- 展開區含:完整推導、每個符號的意義與單位、典型數值、適用條件與限制
- **公式必須可選取複製**(所以用 HTML 不用圖片)

### 公式排版(純 HTML/CSS)

| 需求 | 做法 |
|---|---|
| 下標 | `<sub>` + `font-size: 0.72em; vertical-align: -0.2em` |
| 上標 | `<sup>` 同上,`vertical-align: 0.45em` |
| 分式 | `<span class="frac"><span class="num">a</span><span class="den">b</span></span>`,用 flex column + 中間 border-top |
| 根號 | `√(...)` 直接用字元 + 括號。**不做上劃線**,可讀性足夠且複雜度大降 |
| 積分/求和 | `∫` `∑` 字元 + 上下標 |
| 希臘字母 | 直接用 Unicode 字元(λ ε₀ σ τ α γ ω Γ φ) |
| 向量 | `<span class="vec">E</span>` 加粗斜體 |

**明確決定不做的**:多層嵌套分式、矩陣、複雜的極限符號。本站的公式複雜度不需要,強做只會犧牲可維護性。若真有需要,該公式改用 SVG 圖。

### 提示方塊

五種,樣式一致但色彩與圖示不同:

| 類型 | 圖示 | 色 | 用途 |
|---|---|---|---|
| 工程師直覺 | 💡 | `--pa-primary` | 把公式翻成現場語言 |
| 常見誤解 | ⚠️ | `--pa-warning` | 「錯在哪 / 正解是什麼」 |
| 典型數值 | 📊 | `--pa-text-muted` | 產業常見範圍表 |
| 安全提醒 | 🔴 | `--pa-danger` | 危險氣體、高壓 |
| 延伸 | 📚 | `--pa-info` | 教科書章節、論文 |

**結構統一**:左邊 4 px 色條 + 圖示 + 標題 + 內容。深淺主題下都要維持 ≥ 4.5:1 對比。

**常見誤解方塊有強制格式**:必須明確分成「❌ 常見說法」與「✅ 正確理解」兩段,不能只寫一段模糊的說明。

### 表格

- 斑馬紋用 `--pa-surface-sunken`(極淡)
- 表頭 sticky(長表格捲動時保留)
- 數值欄右對齊、單位獨立一欄或寫在表頭
- **超過視窗寬度時,表格自身橫向捲動**,頁面 body 永不橫向捲動
- 行動版:考慮改為卡片式堆疊(每列一張卡)

### 術語 tooltip

- hover 或 focus 觸發(鍵盤可達)
- 內容:中文名 / 英文名 / 一句話定義 / 「查看完整說明 →」連結
- 底線用 `border-bottom: 1px dotted`,不用實線(避免與連結混淆)
- 行動版:改為點擊觸發,顯示為底部彈出片

### 互動元件容器

```
┌─────────────────────────────────────────┐
│ 🔬 A05 Paschen 曲線互動        [⛶ 全螢幕]│  ← 標題列
├─────────────────────────────────────────┤
│                                         │
│         Canvas / SVG 主視覺區            │
│                                         │
├─────────────────────────────────────────┤
│ 控制面板(滑桿、切換)                    │
├─────────────────────────────────────────┤
│ 📌 觀察點:試著找出這個氣體的最小值…      │  ← 引導文字
└─────────────────────────────────────────┘
```

- 容器有明顯邊界與 `--pa-surface` 背景,與正文區隔
- **標題列固定顯示元件編號**,方便與文件對照
- 「觀察點」用不同背景色,強調這是引導而非說明

## 深色模式

### 切換機制

三態:`auto`(跟隨系統)/ `light` / `dark`。存 localStorage。

```
<html data-theme="dark">   ← JS 在 <head> 內同步設定,避免閃爍
@media (prefers-color-scheme: dark)  ← auto 模式下的預設
:root[data-theme="dark"]             ← 明確指定時覆蓋 media query
```

**防閃爍**:主題判斷腳本必須在 `<head>` 內同步執行(外部檔,但 `<script>` 不加 `defer`),在 CSS 套用前就設好 `data-theme`。

### Canvas 元件的主題適配

Canvas 內容不吃 CSS,必須由 JS 讀取當前 token:

```
getComputedStyle(document.documentElement).getPropertyValue('--pa-text')
```

**每個元件必須監聽主題變更事件並重繪**。這是最容易漏掉的一點 —— 切換主題後粒子還是舊配色,看起來很像 bug。

主題切換時派發自訂事件 `pa:themechange`,所有活著的元件監聽並呼叫自身的 `applyTheme()`。

### 深色模式的特殊處理

- **SVG 圖示與示意圖**:用 `currentColor` 或 CSS 變數上色,不寫死
- **截圖類圖片**:準備深淺兩版,用 `<picture>` + `media` 切換。若只有一版,加淺色邊框避免「白框浮在深色頁上」
- **發光效果**:電漿的輝光在深色模式下更好看,可適度增強;淺色模式下改用較深的飽和色

## 動效

| 動效 | 時長 | 曲線 |
|---|---|---|
| hover / focus 回饋 | 120 ms | `ease-out` |
| 展開/收合 | 200 ms | `cubic-bezier(0.2, 0, 0, 1)` |
| 頁面元素進場 | 260 ms | `ease-out` |
| 主題切換 | 180 ms | `ease` |

**`prefers-reduced-motion: reduce` 時**:
- 所有 CSS transition 時長改為 0.01 ms(不是移除,避免 JS 依賴 transitionend 出錯)
- 互動元件停止自動播放,改為滑桿/單步驅動
- 粒子動畫改為顯示靜態的代表性瞬間 + 向量箭頭
- **所有元件必須在此模式下仍能完整傳達概念** —— 這是驗收條件之一,不是可選項

## 圖示

全部自繪 SVG,線寬 1.5 px,尺寸 20/24 px 兩種,用 `currentColor`。

**不引入圖示字型或圖示庫**。需要的圖示不到 30 個,自繪成本低於引入依賴。

Emoji 只用於內容提示方塊的標記(💡⚠️📊🔴📚🎯🔬✅),不用於 UI 控制項。

## 無障礙檢核清單

實作時每頁必須通過:

- [ ] 所有互動元素可用鍵盤到達與操作,焦點外框清晰可見(2 px `--pa-focus`,不得移除 outline)
- [ ] 標題階層正確(h1 → h2 → h3,不跳級)
- [ ] 圖片與 SVG 有 `alt` 或 `<title>`;裝飾性的加 `aria-hidden="true"`
- [ ] 互動元件有 `aria-label` 與文字狀態摘要
- [ ] 滑桿使用 `<input type="range">` 原生元素(免費得到鍵盤支援與讀屏),或正確的 `role="slider"` + `aria-valuenow`
- [ ] 顏色對比:正文 ≥ 7:1、次要 ≥ 4.5:1、UI 邊界 ≥ 3:1(兩套主題各驗一次)
- [ ] 不以顏色為唯一區辨方式
- [ ] `prefers-reduced-motion` 下所有內容仍可理解
- [ ] 頁面在 200% 縮放下不破版、不橫向捲動
- [ ] 表單/測驗的錯誤訊息與標籤正確關聯

## 列印樣式

工程師會印章節帶進會議。提供 `@media print`:

- 隱藏導覽、側欄、主題切換、互動元件的控制面板
- 互動元件改為顯示其**靜態代表圖 + 一段說明**(元件需提供 `renderStaticFallback()`)
- 強制淺色配色
- 連結後方以 `::after` 顯示 URL
- 公式卡與提示方塊保留但去除背景色,改用邊框
- 分頁避免切斷表格與公式卡(`break-inside: avoid`)
